0x2AB4  struct IpTable<T>

What it is

A longest-prefix-match table for routing, firewall and geolocation data: insert CIDRs with an optional payload, then look addresses up in a few memory reads.

IPv6: 24/8 trie

The FIB6 / DPDK layout: a 224-cell root, then one read per level, /0 to /128.

Zero-copy

Lookups borrow the stored payload: no allocation, no clone, no lock, no T: Clone bound.

SIMD batches

With batch-simd, batches run the AVX-512, AVX2 or NEON kernel detected at runtime.

Insert modes

Replace a payload or deep Merge it, with #[derive(DeepMerge)], a closure or serde.

Snapshots

Save and load tables as compressed XZ snapshots, streamed, with validated input and limits.

How it works

Every cell holds the longest route covering its addresses, so a lookup never backtracks.

  • Cells: a u32 is empty, a route slot, or a group whose sign bit is the flag.
  • Folding: a group whose 256 cells become identical is folded back and reused.
  • Batches: root reads of a whole block first, slot prefetch one chunk ahead, IPv6 lanes in lock step.
  • Single lookups: always scalar, the fastest for one dependent chain of reads.
  • Safety: gather indices are clamped; every unsafe block is justified.

This structure needs a lot of RAM

  • Each family maps a 64 MiB root on its first insertion, even for one route.
  • About 160 B per IPv4 prefix and 1.7 KiB per IPv6 prefix at 1M prefixes.
  • Cap tables with Config::max_routes and max_ipv6_groups.
